## 📋 Status Color Conflicts

### Current Status Colors
- `error`: `#DC2626` (light) / `#F87171` (dark) — Red
- `success`: `#16A34A` (light) / `#34D399` (dark) — Green  
- `warning`: `#B45309` (light) / `#FBBF24` (dark) — Amber

### Which Themes Conflict?

| Theme | Conflict | Solution |
|-------|----------|----------|
| **Indigo** | None | ✅ Safe |
| **Teal** | None | ✅ Safe |
| **Emerald** | Green (success) | Change success to cyan or red |
| **Violet** | None | ✅ Safe |
| **Cyan** | None | ✅ Safe |
| **Orange** | Amber (warning) | Change warning to red or cyan |
| **Lime** | Green (success) | Change success to cyan or red |

### Recommended Status Color Swaps

**If choosing Emerald or Lime (green accent):**
```javascript
// Option A: Use Cyan for success
success: '#06B6D4'    // cyan (success = trust)

// Option B: Use Red for success
success: '#DC2626'    // red (use emerald/lime for growth, red for success)

// Option C: Use different green shade
success: '#059669'    // darker emerald (but less distinguishable from accent)
```

**If choosing Orange (warm accent):**
```javascript
// Option A: Keep current, just ensure visual separation
warning: '#D97706'    // amber-600 (shift darker to distinguish from orange)

// Option B: Switch to cyan
warning: '#0891B2'    // cyan (new warning = attention)

// Option C: Switch to red
warning: '#DC2626'    // red (traditional warning color)
```

## 🚀 Implementation Checklist by Theme

### For Any Theme Change:

- [ ] Update `ThemeContext.jsx` (4 accent tokens × 2 themes)
- [ ] Update `COLORS.md` documentation
- [ ] Update hardcoded palettes in:
  - [ ] `LoginScreen.jsx`
  - [ ] `ConnectScreen.jsx`
  - [ ] `AccountSettingsScreen.jsx`
- [ ] Run contrast checker: `node services/dashboard/src/theme/scripts/check-contrast.mjs`
- [ ] Test in both light and dark modes
- [ ] Visual QA: buttons, badges, hover states, modals
- [ ] Check status color conflicts (see table above)
- [ ] Mobile responsiveness check
- [ ] Cross-browser test (Chrome, Firefox, Safari)
- [ ] Get stakeholder sign-off
- [ ] Deploy to staging first
- [ ] Monitor user feedback

## 💡 Pro Tips

### Testing Before Commit
1. Use browser DevTools to temporarily swap colors:
   ```javascript
   // In console (light mode):
   document.documentElement.style.setProperty('--accent', '#0D9488');
   ```

2. Toggle dark mode to see both variants

3. Screenshot both modes for design review

### Accessibility Validation
- Use WebAIM Contrast Ratio tool
- Test with color-blindness simulators (Sim Daltonism, Color Oracle)
- Ensure status colors remain distinct

### Brand Consistency
- Document choice in `COLORS.md` (why this theme was chosen)
- Keep old recipes as comments for future reference
- Add decision date and stakeholder sign-off

## 🎯 Final Recommendation

**If you had to pick ONE:**

1. **Stay Safe → INDIGO** ✅ (current, proven, enterprise-safe)
2. **Go Modern → TEAL** 🌊 (approachable, trendy, SaaS-friendly)
3. **Go Bold → ORANGE** 🟠 (action-oriented, legacy brand callback)
4. **Go Eco → LIME** 💚 (modern, vibrant, growth-focused)

**For conservative enterprises:** Indigo or Teal  
**For growth-focused startups:** Lime or Teal  
**For action-driven messaging:** Orange  
**For infrastructure/DevOps:** Cyan  
**For premium positioning:** Violet
