# 2.16-1 — Terraform ECR Repositories

> Must be done first. CI pipeline pushes images to ECR — nothing else can deploy until repos exist.

---

## What to build

Three ECR private repositories:
- `axiaops-api`
- `axiaops-ingestion`
- `axiaops-dashboard`

---

## File structure

```
terraform/
  backend.tf          — S3 + DynamoDB state backend
  providers.tf        — AWS provider, region
  variables.tf        — var.aws_region, var.aws_account_id, var.env
  ecr.tf              — the three repos
  outputs.tf          — registry URL output
```

---

## terraform/backend.tf

```hcl
terraform {
  backend "s3" {
    bucket         = "axiaops-terraform-state"
    key            = "prod/terraform.tfstate"
    region         = "eu-central-1"
    dynamodb_table = "axiaops-terraform-locks"
    encrypt        = true
  }
}
```

> Bootstrap: create the S3 bucket and DynamoDB table manually once before `terraform init`.
> ```bash
> aws s3api create-bucket --bucket axiaops-terraform-state \
>   --region eu-central-1 \
>   --create-bucket-configuration LocationConstraint=eu-central-1
> aws s3api put-bucket-versioning --bucket axiaops-terraform-state \
>   --versioning-configuration Status=Enabled
> aws dynamodb create-table \
>   --table-name axiaops-terraform-locks \
>   --attribute-definitions AttributeName=LockID,AttributeType=S \
>   --key-schema AttributeName=LockID,KeyType=HASH \
>   --billing-mode PAY_PER_REQUEST \
>   --region eu-central-1
> ```

## terraform/ecr.tf

```hcl
locals {
  repos = ["axiaops-api", "axiaops-ingestion", "axiaops-dashboard"]
}

resource "aws_ecr_repository" "repos" {
  for_each             = toset(local.repos)
  name                 = each.key
  image_tag_mutability = "MUTABLE"

  image_scanning_configuration {
    scan_on_push = true
  }
}

resource "aws_ecr_lifecycle_policy" "cleanup" {
  for_each   = aws_ecr_repository.repos
  repository = each.value.name

  # Rule 1: keep the last 15 SHA-tagged images per repo.
  # deploy:production pushes both :<sha> and :latest — using a tagged rule
  # prevents :latest from consuming a slot in the count.
  #
  # Rule 2: expire untagged images after 1 day.
  # Untagged layers are left behind when :latest is overwritten on each deploy.
  policy = jsonencode({
    rules = [
      {
        rulePriority = 1
        description  = "Keep last 15 tagged images"
        selection = {
          tagStatus     = "tagged"
          tagPatternList = ["*"]
          countType     = "imageCountMoreThan"
          countNumber   = 15
        }
        action = { type = "expire" }
      },
      {
        rulePriority = 2
        description  = "Expire untagged images after 1 day"
        selection = {
          tagStatus   = "untagged"
          countType   = "sinceImagePushed"
          countUnit   = "days"
          countNumber = 1
        }
        action = { type = "expire" }
      }
    ]
  })
}
```

## After apply — add GitLab CI variables

| Variable | Value | Masked |
|----------|-------|--------|
| `AWS_ACCOUNT_ID` | your account ID | yes |
| `AWS_DEFAULT_REGION` | `eu-central-1` | no |
| `AWS_ACCESS_KEY_ID` | AxiaOpsCI user key | yes |
| `AWS_SECRET_ACCESS_KEY` | AxiaOpsCI user secret | yes |

The CI pipeline already constructs `ECR_REGISTRY` as `${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_DEFAULT_REGION}.amazonaws.com` — no changes to `.gitlab-ci.yml` needed.

## GitLab Container Registry — cleanup policy

The CI pipeline uses the GitLab registry (`$CI_REGISTRY_IMAGE`) as an intermediate store:
`build:images` pushes there; `deploy:production` pulls, re-tags, and pushes to ECR.
Without a cleanup policy, every build on `main`/`develop` accumulates a tagged image indefinitely.

### Configure via GitLab API (one-time, run from your terminal)

```bash
# Requires a personal access token with api scope.
# Keep tags newer than 90 days, always retain the last 10.
curl --request PUT \
  --header "PRIVATE-TOKEN: <your_personal_access_token>" \
  --header "Content-Type: application/json" \
  --data '{
    "container_expiration_policy_attributes": {
      "enabled": true,
      "cadence": "1d",
      "keep_n": 10,
      "older_than": "90d",
      "name_regex_delete": ".*",
      "name_regex_keep": ""
    }
  }' \
  "https://gitlab.com/api/v4/projects/<project_id>"
```

Replace `<your_personal_access_token>` and `<project_id>` (find it under **Settings → General → Project ID**).

### Or configure via GitLab UI

**Settings → Packages & Registries → Container Registry → Cleanup policies**

| Setting | Value |
|---------|-------|
| Enabled | Yes |
| Run cleanup | Every day |
| Keep the most recent | 10 tags |
| Remove tags older than | 90 days |
| Tags to remove | `.*` (all) |
| Tags to keep | *(leave blank)* |

This mirrors the ECR policy: recent builds (last 10 / 90 days) are always retained, older images self-clean without manual intervention.
