# 2.16-5 — Secrets Manager

> Store all sensitive config in AWS Secrets Manager.
> App Runner reads secrets at container startup via `runtime_environment_secrets` — no env vars in Terraform state.
> Do this before App Runner (2.16-3) — the apprunner.tf references these secret ARNs.

---

## Secrets to create

| Secret name | Used by | Value |
|-------------|---------|-------|
| `axiaops/prod/database-url` | api, ingestion | `postgres://axiaops:PASSWORD@RDS_HOST:5432/axiaops?sslmode=require` |
| `axiaops/prod/migration-database-url` | api, ingestion | `postgres://axiaops_owner:PASSWORD@RDS_HOST:5432/axiaops?sslmode=require` |
| `axiaops/prod/encryption-key` | api, ingestion | 32-byte hex — `openssl rand -hex 32` |
| `axiaops/prod/redis-url` | api, ingestion | ElastiCache endpoint (add after ElastiCache is provisioned) |
| `axiaops/prod/kinde-issuer` | api | `https://axiaops.kinde.com` |

> `KINDE_CLIENT_ID` is not a secret — it's a public OAuth client ID baked into the dashboard build. No need to store in Secrets Manager.

## ElastiCache Serverless (Redis)

Add to `terraform/secrets.tf` or a separate `elasticache.tf`:

```hcl
resource "aws_elasticache_serverless_cache" "redis" {
  engine = "redis"
  name   = "axiaops-prod"

  cache_usage_limits {
    data_storage {
      maximum = 1
      unit    = "GB"
    }
    ecpu_per_second {
      maximum = 1000
    }
  }

  subnet_ids         = aws_subnet.public[*].id
  security_group_ids = [aws_security_group.redis.id]
}

resource "aws_security_group" "redis" {
  name   = "axiaops-redis-sg"
  vpc_id = aws_vpc.main.id

  ingress {
    from_port   = 6379
    to_port     = 6379
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}
```

After apply, update the `redis_url` secret:

```bash
REDIS_ENDPOINT=$(terraform output -raw elasticache_endpoint)
aws secretsmanager put-secret-value \
  --secret-id axiaops/prod/redis-url \
  --secret-string "rediss://${REDIS_ENDPOINT}:6379"
```

> Note: ElastiCache Serverless uses TLS — `rediss://` (double s), not `redis://`.

## ENCRYPTION_KEY rotation procedure

> Document in `docs/ops.md` before launch.

1. Generate new key: `openssl rand -hex 32`
2. Write a one-off migration script that:
   - Reads every row from `accounts` where `secret_encrypted != ''`
   - Decrypts with old key using `shared/crypto`
   - Re-encrypts with new key
   - Updates the row
3. Run the script against production RDS **before** updating the secret
4. Update `axiaops/prod/encryption-key` in Secrets Manager
5. Redeploy both App Runner services to pick up the new secret

## Verify

```bash
# Check secrets exist
aws secretsmanager list-secrets --region eu-central-1 \
  --query "SecretList[?starts_with(Name, 'axiaops/prod')].[Name]" \
  --output table

# Fetch a secret value (confirm it's correct)
aws secretsmanager get-secret-value \
  --secret-id axiaops/prod/kinde-issuer \
  --query SecretString --output text
```

```
1. terraform apply  (creates secrets with placeholder values)
2. terraform apply  (after RDS is up — database_url and migration_database_url get real values)
3. Update redis_url after ElastiCache is provisioned
4. Apply apprunner.tf (references secret ARNs — must exist first)
```
