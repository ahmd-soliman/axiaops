# 2.16-2 — RDS PostgreSQL + Migrations

> Provision the production database and run versioned migrations against it.

---

## What to build

- RDS PostgreSQL 16 `db.t4g.micro` in `eu-central-1`
- VPC with public subnets (no NAT Gateway — App Runner uses public subnets)
- Security group allowing App Runner → RDS on port 5432
- Run migrations via `MIGRATION_DATABASE_URL` on first deploy

    cidr_block = "0.0.0.0/0"

## terraform/rds.tf

```hcl
resource "aws_db_subnet_group" "main" {
  name       = "axiaops-db-subnet-group"
  subnet_ids = aws_subnet.public[*].id
}

resource "aws_security_group" "rds" {
  name   = "axiaops-rds-sg"
  vpc_id = aws_vpc.main.id

  ingress {
    from_port   = 5432
    to_port     = 5432
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]  # App Runner uses public IPs — restrict further once VPC connector is added
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

resource "aws_db_instance" "postgres" {
  identifier              = "axiaops-prod"
  engine                  = "postgres"
  engine_version          = "16"
  instance_class          = "db.t4g.micro"
  allocated_storage       = 20
  max_allocated_storage   = 100
  storage_type            = "gp3"
  storage_encrypted       = true

  db_name  = "axiaops"
  username = "axiaops_owner"
  password = var.db_owner_password  # sensitive — set in tfvars, stored in Secrets Manager

  db_subnet_group_name   = aws_db_subnet_group.main.name
  vpc_security_group_ids = [aws_security_group.rds.id]
  publicly_accessible    = true  # required until App Runner VPC connector is configured

  backup_retention_period = 7
  backup_window           = "03:00-04:00"
  maintenance_window      = "Mon:04:00-Mon:05:00"

  deletion_protection = true
  skip_final_snapshot = false
  final_snapshot_identifier = "axiaops-prod-final"

  enabled_cloudwatch_logs_exports = ["postgresql"]

  tags = { Name = "axiaops-prod" }
}
```

## Running migrations against production RDS

Migrations run automatically on service startup via `MIGRATION_DATABASE_URL`. For the first deploy, run manually:

```bash
# From your local machine with RDS publicly accessible
MIGRATION_DATABASE_URL="postgres://axiaops_owner:PASSWORD@RDS_ENDPOINT:5432/axiaops?sslmode=require" \
  go run ./services/api/cmd/main.go
```

Or add a one-shot migrate target to the Makefile:

```makefile
migrate-prod:
	MIGRATION_DATABASE_URL="$(MIGRATION_DATABASE_URL)" \
	  go run ./services/shared/storage/postgres/migrate.go
```

> The `axiaops` app user and schema are created by migration `000_init.up.sql` — no manual SQL needed.

## Current migrations (in order)

| File | What it does |
|------|-------------|
| `000_init.up.sql` | Creates `axiaops` app user, schema, grants |
| `001_initial.up.sql` | All tables + RLS policies |
| `002_ghost_snapshots.up.sql` | `ghost_snapshots` table |
| `004_add_scan_interval.up.sql` | `scan_interval_hours` on accounts |
| `005_add_cost_records_index.up.sql` | Index on `(tenant_id, period_end)` |

> Migration `003` was skipped — gap is intentional, golang-migrate handles it fine.
