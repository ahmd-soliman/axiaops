# Breached-password corpus — provenance & regeneration runbook

Provenance manifest and regeneration ceremony for the embedded breached-password
corpus the `breachlist` package screens against. For the design
rationale — why offline-embedded instead of the live HIBP k-anonymity API — see
[`docs/password-breach-check-design.md`](password-breach-check-design.md).

This is a *runbook* + a *manifest*. Modeled on
[`docs/license-issuance.md`](license-issuance.md).

---

## What is embedded

`services/api/internal/breachlist/breached-passwords.bin` — a sorted,
concatenated stream of **raw 20-byte SHA-1 digests**, no delimiters, binary-
searched by `breachlist.IsCompromised`. SHA-1 is the **corpus index only**; AxiaOps
stores passwords with argon2id (`auth.Hash`), never SHA-1.

The blob is linked into **two** shipped images — the tenant `api` binary
(`cmd/`) and the `api-admin` staff-plane binary (`cmd/api-admin/`) — because both
call `auth.CheckPolicy`. `cmd/hash-password` links it too (operator tooling, not
a pulled service image). Ingestion does **not** link it: `breachlist` lives under
`services/api/internal`, which ingestion's import graph never references, so the
blob is structurally absent from ingestion's link set (not a dead-code-elimination
gamble).

> misses the mid/long tail the full HIBP top-1M would cover; that gap is an
> accepted trade, reversible anytime via the optional swap below with **no code
> change**.

## Verify the committed asset

```bash
sha256sum services/api/internal/breachlist/breached-passwords.bin
#   → must match the SHA-256 in the manifest above
wc -c < services/api/internal/breachlist/breached-passwords.bin   # → 6760
```

The package's `TestCorpusInvariants` additionally asserts at test time that the
blob length is a multiple of 20 and the records are strictly sorted ascending
(the binary-search invariant); `TestKnownVectorPassword` asserts the end-to-end
encoding is correct (`IsCompromised("password") == true`).

## Regenerate from the seed (no source change)

If you edit `seed-wordlist.txt` (add/remove entries):

```bash
scripts/gen-breachlist.sh           # SEED mode (default)
# → prints the new N, byte size, and SHA-256
```

Then update the **Current manifest** table above (N, size, SHA-256, date) and
commit the regenerated `.bin` together with the wordlist change. Review the
`git diff --stat` — the `.bin` is binary, so the manifest table + the wordlist
diff ARE the human-reviewable record of what changed.

## Swap in the real HIBP top-1M (OPTIONAL future upgrade)

> **Not required.** The ~10k embedded corpus (above) is the chosen production
> posture — see the Decision in
> [`docs/password-breach-check-design.md`](password-breach-check-design.md).
> This swap is an optional coverage upgrade for a future date (e.g. a
> security-conscious customer requirement), kept here so it's a turnkey
> regeneration when/if it's wanted. It is **not** a pending obligation.

1. **Download** HIBP's prevalence-ordered hash file. Either:
   - `HaveIBeenPwned/PwnedPasswordsDownloader` in **ordered** mode
     (`haveibeenpwned-downloader -o pwned-passwords-ordered.txt`), or
   - the published torrent of the ordered SHA-1 file.

   The downloader tool is **not** embedded — only the resulting digests are — so
   its (separate) licence does not propagate into our binary. Only the *data* is
   embedded, and the HIBP data is **CC BY 4.0** (attribution in `NOTICE`).

2. **Generate** the top-N (default 1,000,000 → ~20 MB):

   ```bash
   scripts/gen-breachlist.sh hibp /path/to/pwned-passwords-ordered.txt 1000000
   ```

   The generator strips the `:count` suffix, hex-decodes each uppercase-hex line
   to raw 20 bytes, **re-sorts ascending by raw digest** (binary search needs
   digest order, not prevalence order), dedupes, and writes the `.bin`.

   - **Size knob:** 1,000,000 → ~20 MB (paid in *both* the api and api-admin
     images). The 500k fallback (`… 500000` → ~10 MB) is the same code with a
     smaller N if the 20 MB image bump proves heavy — see the design doc.

3. **Update this manifest** — Source row → "HIBP Pwned Passwords, ordered,
   version/date <X>"; N; size; the new SHA-256; date. Update `NOTICE` with the
   HIBP corpus version/date.

4. **Re-run the size diff** on both binaries and note the delta:

   ```bash
   make build-production   # builds ./cmd/ and ./cmd/api-admin/ with -tags production
   ls -l /tmp/axiaops-api-production /tmp/axiaops-api-admin-production
   ```

5. Commit the `.bin` + manifest + `NOTICE` together. Re-screening cadence:
   regenerate each minor release, or when HIBP publishes a major corpus update.

## Invariants you must not break

- **Raw 20-byte records, sorted ascending, no delimiters.** The lookup
  binary-searches raw digests; hex strings or unsorted records silently break it.
- **No normalization.** The generator hashes the exact bytes of each line
  (minus a single trailing CR); `IsCompromised` hashes the exact `[]byte` of the
  candidate; `auth.Hash` stores the exact same bytes. If anyone adds
  TrimSpace/Unicode-NFC to one path, add it to all three or the screen checks a
  different string than the one stored.
- **Unconditional embed.** `embed.go` has no build-tag split — the corpus ships
  in every build, including `-tags production`. Making it optional would let an
  operator build a NIST-non-compliant binary.
